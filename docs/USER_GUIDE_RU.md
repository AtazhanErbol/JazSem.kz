# JazSem: ручное создание курсов и восстановление пароля

## Работа преподавателя без AI

1. Администратор создаёт дисциплину и назначает ей преподавателя. Без назначенной дисциплины преподаватель не сможет создать курс.
2. Преподаватель открывает **Мои курсы → Создать**, задаёт название, описание, дисциплину и язык.
3. В карточке курса открывает **Редактор курса**. Добавляет неделю, внутри неё — тему. Номер следующей недели подставляется автоматически, его можно изменить.
4. В теме нажимает **+ Материалы**, **+ Задания** или **+ Тесты**. Изменения сохраняются как черновик; AI не нужен.
5. Для задания задаёт название, инструкцию, максимальный балл, срок сдачи и возможность поздней сдачи. Студент отправляет текст или файлы. Преподаватель оценивает работу или возвращает её с комментарием на доработку.
6. Для теста задаёт время, число попыток, проходной процент, даты доступности и перемешивание. Затем выбирает созданный тест в дереве слева, нажимает **Добавить вопрос**, выбирает один или несколько правильных ответов и добавляет минимум два варианта. Правильные варианты отмечает флажком. Для каждого вопроса можно задать балл и пояснение. Вопросы и варианты сразу появляются в редакторе.
7. В блоке **Схема оценивания** создаёт схему и компоненты, например задания 50%, тесты 50%. Сумма должна быть 100%. Компонент итогового теста требует тест с отметкой «Итоговый».
8. Нажимает **Опубликовать**. Сервер проверяет заполнение тем, материалов, вопросов, ответов и схему оценивания. При ошибке показывает причину; черновик сохраняется.
9. В блоке **Назначить** выбирает своего студента либо группу. Студент получает доступ и уведомление. Для нового студента сначала создайте аккаунт в разделе **Студенты**.
10. Опубликованная версия защищена от редактирования. Для изменений создайте **Новую версию**; уже назначенные студентам версии сохраняются.

Разделы **Задания** и **Тесты** содержат списки активностей и ссылку «Выбрать курс» с объяснением ручного создания. Учебные материалы принадлежат теме курса; их не нужно создавать через AI-конструктор.

## Пароль и письма

- **Забыли пароль?**: пользователь вводит email своего аккаунта. Для активного аккаунта формируется письмо со ссылкой; ответ страницы одинаков для существующего и неизвестного email.
- Ссылка действует один час, после успешной смены повторное использование невозможно. Новый пароль нужно ввести дважды.
- После смены приходит отдельное уведомление. Сам новый пароль в письме не отправляется.
- В профиле отдельная карточка **Безопасность** позволяет изменить пароль с подтверждением текущего.
- Студенту отправляются письма о назначении курса, результате теста, проверке/доработке работы и приближении срока задания.
- Преподавателю — о новой сданной работе. Администратору — о неудачной генерации AI. Внутренние уведомления доступны в интерфейсе.
- Письма идут на email, записанный в аккаунте пользователя. Настройка адреса отправителя не меняет адреса аккаунтов.
- Письма помещаются в зашифрованную очередь. Планировщик запускает обработку каждую минуту. Неудачная отправка повторяется, максимум пять попыток. Получение внешним почтовым ящиком зависит от SMTP и почтового сервиса; абсолютная гарантия доставки не заявляется.

### Gmail / Google Workspace

Локально подготовлены SMTP Gmail, порт 587 и TLS. Для реальной отправки нужен пароль приложения Google; обычный пароль от аккаунта не подходит для этого способа. Он вводится только на компьютере, не в чат и не в Git.

```powershell
./scripts/configure-gmail.ps1 -Sender 'your-address@gmail.com'
```

Скрипт запросит пароль скрытым вводом, сохранит его в игнорируемый `.env.local`. После этого перезапустите Django и Celery worker/beat. Для пароля приложения нужна двухэтапная аутентификация; некоторые политики Workspace запрещают этот способ. Инструкция Google: https://support.google.com/mail/answer/185833?hl=ru

**До настройки SMTP-пароля локальный режим сохраняет письма в `.runtime/emails`, внешней доставки нет.** Эти файлы могут содержать ссылки сброса и временные пароли; не публикуйте их. Уже записанные в файлы письма автоматически через Gmail повторно не отправляются — после настройки запросите новую ссылку.

Для получателей на другом устройстве нужен публичный HTTPS-адрес сайта в `FRONTEND_URL`; ссылка `127.0.0.1` работает только на этом компьютере.

## Запуск локально на Windows

Существующее окружение Python располагается рядом с репозиторием в `../venv`. Установите зависимости из `backend/requirements.txt`, включая условную Windows-зависимость pywin32, и зависимости frontend. Скрипт не устанавливает их автоматически.

```powershell
./scripts/start-local.ps1
```

Скрипт использует существующую локальную БД `../e2e-release.sqlite3`, выполняет миграции и запускает Django, Vite, Celery worker и beat скрытыми процессами. Порты — 8000 и 5173. Логи и PID находятся в `.runtime`. Если порты заняты, сначала остановите прежние процессы проекта; скрипт не завершает чужие процессы автоматически. Можно передать `-DatabasePath` с другой БД. Тестовые аккаунты создаются только при явном `-Seed` и заданном `DEV_SEED_PASSWORD`.

Локальная файловая очередь позволяет запускать проект без Docker и Redis. Это режим разработки для одного компьютера. Для production сохранена схема PostgreSQL + Redis + Celery и отдельные production settings; Windows solo worker не заменяет production-инфраструктуру.

## AI, контент, аудит и backend

**AI-конструктор** показывает доступность генерации, настройки и фоновый обработчик. Если AI отключён или обработчик недоступен, система не создаёт заведомо нерабочую задачу. Загрузка и извлечение текста отделены от платной генерации. В текущем локальном запуске генерация выключена (`AI_ENABLED=false`); платные запросы при проверках не выполнялись. Для включения нужны ключ, модель, цены для учёта бюджета и дневной лимит. Сканированные PDF/изображения дополнительно требуют Tesseract и языковые пакеты; качество OCR и живую генерацию эта проверка не подтверждает.

**Контент** — информационные блоки публичной главной страницы на RU/KZ, которыми управляет администратор. Это не раздел учебных материалов.

**Аудит** — доступный администратору журнал важных действий с аккаунтами, курсами и оценками: автор, время, изменение. Не каждое чтение страницы журналируется.

**Backend — Django + Django REST Framework.** React-интерфейс обращается к `/api/v1/`, локальный Vite перенаправляет запросы на Django:8000. Django проверяет сессию, CSRF, роль и доступ к данным, выполняет действия и работает с БД. Локально — SQLite, production-конфигурация — PostgreSQL. Долгие задачи и письма выполняет Celery.

## Проверка и границы

Проверены серверные роли/доступы, ручной учебный цикл, публикация, оценки, одноразовый сброс пароля и уведомление после смены, зашифрованная очередь и повтор после ошибки SMTP, запрет AI при отключённой генерации/обработчике. Браузерные тесты выполнялись на отдельной БД, пользовательская БД не сбрасывалась.

Реальная доставка Gmail не подтверждена: пароль приложения не предоставлен. Платная генерация OpenAI и production-развёртывание в рамках этой проверки не выполнялись.
