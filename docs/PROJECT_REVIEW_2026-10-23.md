## Учебные сценарии и соответствие требованиям

- `accounts`: преподаватель создаёт студентов; администратор управляет пользователями. Есть импорт из Excel, блокировка и восстановление пароля. Временный пароль отправляется через зашифрованную почтовую очередь.
- `academics` / `enrollments`: группы и индивидуальные назначения сосуществуют; происхождение назначения сохраняется. У студента один преподаватель-владелец; назначение требует соответствия владельцу курса/группы.
- `courses`: опубликованная версия неизменяема, изменения идут через новый черновик. Назначения закреплены за версией. Есть явное обновление студентов с сопоставлением содержимого и сохранением результатов; незавершённые тесты блокируют такой перенос.
- `assignments`: ответы, файлы, ручная оценка, комментарии и доработка с историей попыток.
- `testing`: серверный таймер, сохранение ответов, фиксированное перемешивание, ограничение попыток и автоматическая проверка точного набора ответов. Эти учебные таймеры не относятся к ограничению длительности ИИ.
- `grading`: настраиваемые веса компонентов для версии курса, сумма 100%; отсутствующие работы дают ноль, для тестов берётся лучшая оценённая попытка, для заданий — последняя оценённая. Это уже реализованные бизнес-правила, которых ещё не было в архивном ТЗ.
- `progress`: прогресс рассчитывается по обязательным материалам и активностям отдельно от итоговой оценки.
- `ai`: выбор источников, страницы PDF, инструкции, новый курс или добавление недель, повторная генерация темы, редактор черновика, подтверждение импорта. Публикация курса остаётся отдельным действием.
- `cms`: языковые черновики лендинга, предпросмотр и публикация. Контакты и юридические сведения требуют реальных данных владельца.

По основным сценариям это работающая образовательная платформа. Заявлять полное соответствие каждой детали исходного ТЗ пока нельзя: ниже перечислены конкретные пробелы.

## Что изменено по запросу о длительности ИИ

| Ограничение до изменения | Новое поведение |
| --- | --- |
| OpenAI: 180 секунд на запрос | `timeout=None` при создании клиента для генерации курса и повторной генерации темы. |
| Celery: 480 секунд soft / 540 секунд hard на ИИ-задачи | Обе ИИ-задачи работают без ограничения длительности. Убраны также глобальные pool defaults, которые Billiard мог повторно применить даже при task limit=0. |
| PDF: 420 секунд суммарно | Проверки истекшего времени нет. |
| Tesseract: 60 секунд на операцию | OCR запускается без таймера. |
| Истечение ownership через 600 секунд во время ожидания модели | Отдельный поток каждые 30 секунд продлевает lease во время генерации, парсинга и OCR. 600 секунд теперь означают отсутствие heartbeat, а не максимальную длительность задачи. |
| SENT-задача могла исчерпать попытки, ожидая занятый heavy worker | Пока в heavy-очереди работает задача с действующим lease, отправленные задачи продолжают ждать без расходования повторов из-за ожидания. |

После гибели worker heartbeat прекращается и восстановление сохраняется. Запрос после возможного платного обращения не повторяется автоматически. Поздний результат не отменяет пользовательскую отмену и учитывается в расходах. Отмена во время сетевого вызова логическая: она не гарантирует немедленную остановку вычислений у провайдера или освобождение heavy worker.

Модель сохранена: **`gpt-5-nano`**, reasoning effort: **`low`**. Действующие настройки объёма/расходов сохранены: 8 000 выходных токенов на курс, 4 000 на тему, 40 000 символов контекста, 5 генераций в UTC-сутки на пользователя, бюджет приложения $0.25 в UTC-сутки. Ограничения файлов, памяти и CPU также сохранены. Внешние ошибки API/сети, ограничения провайдера и OOM по-прежнему возможны; снято именно ограничение времени в приложении.

Конфигурация таймаутов сверена с [официальной документацией Python SDK OpenAI](https://developers.openai.com/api/reference/python) и установленным SDK 3.19.2. Конструктор принимает `None`; проверка созданного клиента показала `Timeout(timeout=None)`. Изменений модели, API-ключей, базы данных или миграций нет.

## Обнаруженные ограничения и последующие задачи

1. **Критерии оценки заданий не представлены отдельной структурой.** В `backend/apps/ai/schema.py:AssignmentDraft` есть название, инструкция и источники; в `backend/apps/assignments/models.py:Assignment` нет полей/модели рубрики и весов критериев. Критерии можно описать текстом инструкции, но их отдельная генерация, редактирование и оценка по критериям из ТЗ не реализованы.

2. **Отказы до вызова и явные отказы API первоначально показывались как неопределённый платный вызов. Исправлено в продолжении работы 23.10.2026.** Отдельные безопасные коды теперь различают исчерпанный локальный бюджет, ошибки настройки, кредиты/квоты OpenAI, частотные ограничения и другие явные отклонения. Подтверждённый отказ освобождает только резерв своего запроса и записывает REJECTED с нулевой стоимостью. Сетевые и неопределённые серверные сбои сохраняют резерв и не повторяются автоматически.

3. **Проверка доступности worker не различает очереди.** `backend/apps/common/background.py:worker_available` считает достаточным ping любого Celery worker. Если доступен только short worker, интерфейс ИИ может сообщать готовность, хотя heavy-очередь некому обрабатывать. Проверку стоит связать с heavy role/очередью.

4. **После ошибки polling автоматически прекращается.** В `frontend/src/features/ai/AIWizard.tsx` интервалы обновления источников, истории и текущей задачи отключаются при `q.state.error`. После исчерпания обычных query retries кратковременный сетевой сбой может оставить экран без дальнейших обновлений до ручного повтора/перезагрузки. Желателен ограниченный backoff с восстановлением polling.

5. **Бизнес-правила оценивания следует подтвердить для реального учебного процесса.** Для нового ИИ-курса `backend/apps/ai/services.py:import_draft` по умолчанию создаёт 50/50 для заданий и тестов либо 100% для одного вида. Веса редактируются, но это конкретное начальное правило; в архивном ТЗ формула оставалась нерешённой. Аналогично следует подтвердить учёт пропусков, лучшей тестовой и последней проверенной письменной попытки.

6. **Есть ограничения первой версии.** Один преподаватель-владелец студента; одно enrollment на пару студент/курс; отдельный сценарий повторного зачисления ещё не спроектирован. Удаление пользовательского доступа не должно удалять учебную историю. Эти ограничения документированы и требуют учёта при работе нескольких кафедр/преподавателей.

7. **Production-приёмка остаётся отдельной задачей.** Старый `docs/RELEASE_CANDIDATE.md` не подтверждает текущие образы и внешнюю инфраструктуру. В репозитории срок предыдущего native-image review — 15.10.2026, он уже истёк. Это факт о сохранённом review, а не новая проверка CVE. Нужны свежий скан образов, проверка целевых PostgreSQL/Redis/S3/TLS, реальной почты, backup/restore и качества ИИ на материалах RU/KK. Новые исследования уязвимостей и платные запросы в рамках этой работы не выполнялись.
