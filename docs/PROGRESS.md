# Реализация и проверки

Дата локальной проверки: 25 сентября 2026. Репозиторий создан с нуля. Статус: рабочая реализация для staging-приёмки; production-развёртывание ещё не проверено.

## Этапы

1. Архитектура и схема данных: модульный Django/DRF, React/TypeScript, PostgreSQL, Redis/Celery, private S3. Принятые бизнес-решения записаны в DECISIONS.md.
2. Основа: конфигурации development/test/production, миграции, Docker/Compose, CI, OpenAPI, единый формат ошибок, request IDs и audit.
3. Аккаунты: session/CSRF, роли, ownership, временный пароль, восстановление пароля, шифрованный email outbox.
4. Учебная структура: дисциплины, группы, версии курсов, редактор недель/тем/материалов, копирование версии, проверяемая публикация и назначения с наследованием группой.
5. Обучение: приватные файлы, задания и доработка, серверные попытки тестирования, сохраняемые ответы, перемешивание, таймер, автопроверка, отдельные оценки и прогресс.
6. AI: загрузка/извлечение/OCR, чанки с источниками, асинхронные задания, structured drafts, визуальное редактирование, регенерация темы, подтверждение в новую версию. Публикация остаётся отдельным действием преподавателя.
7. Интерфейс: адаптивные главная страница и кабинеты, русский/казахский, состояния загрузки/ошибки/пустого списка, реальные API-данные.
8. Проверка: unit/API/browser tests, сборка, миграции на пустой SQLite, визуальная проверка desktop/mobile, документация запуска и резервного копирования.

## Подтверждено локально

- Backend: 29 pytest tests; ruff lint/format; Django system check.
- Миграции применены на пустой локальной БД; makemigrations --check без изменений.
- OpenAPI validation: 0 ошибок; 2 предупреждения об именовании language enums.
- Frontend: ESLint, TypeScript, 2 Vitest tests и production build.
- Chromium E2E: 4 сценария — преподаватель создаёт курс/неделю/тему/материал; студент читает, сдаёт задание и тест, преподаватель оценивает; AI review/import с тестовым API; главная на ширинах 390/768/1280/1440 и переключение языка.
- Проверены запреты доступа между преподавателями/студентами, неизменяемость опубликованной версии, отсутствие ключей правильных ответов у студента, приватные downloads, подмена foreign keys, дедупликация назначений и лимиты AI.
- Исправлены найденные ошибки: CSRF refresh больше не расходует login quota; состояние выбранного ответа сохраняется сразу; чтение темы имеет собственный progress marker.

## AI и расходы

Реальных запросов к OpenAI при разработке не выполнялось. Ключ владельца хранится только в игнорируемом локальном `.env`. AI выключен. Подготовлен `gpt-5-nano`, лимиты токенов, один повтор и суточное резервирование бюджета $0.25 для всего приложения. Подробности и официальный источник тарифов — в AI_COSTS.md.

## Обязательная staging-приёмка

- Запуск Docker images/Compose на Linux; Docker в текущей среде отсутствует.
- PostgreSQL: CI и отдельные конкурентные запросы (назначения, попытки, публикация, бюджет). Локальные тесты использовали SQLite и не доказывают поведение блокировок PostgreSQL.
- Реальные Redis/Celery worker/beat, перезапуск worker и зависшие задания; в unit tests используются eager tasks/fakes.
- Private S3/MinIO, SMTP/TLS, OCR Tesseract RU/KZ/EN на реальных PDF/DOCX/PPTX/изображениях.
- Реальный OpenAI draft на небольшом материале после явного включения AI; оценка точности, качества казахского и полноты ссылок на источники. Сейчас provider покрыт тестовым ответом, не живым вызовом.
- HTTPS, secure cookies, production health/readiness, наблюдаемость, нагрузочные проверки, проверка безопасности и восстановление backup.
- Финальная языковая/предметная редактура, реальные контакты и юридические тексты владельца.

Параметры инфраструктуры задаются environment. Production-ready статус нельзя выводить только из успешной локальной сборки; инструкция приёмки находится в DEPLOYMENT.md.
