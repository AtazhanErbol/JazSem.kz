## Открытые замечания по приоритетам

### P1 — устранить до production-приёмки

**A-01. Потерянные/зависшие фоновые задачи. ТЗ 43–45, 103.**

Основание: `backend/apps/ai/views.py` отправляет задачи через `transaction.on_commit(...delay...)` после сохранения записи; `backend/apps/ai/tasks.py` принимает только QUEUED, переводит в PROCESSING; recovery/lease/watchdog для зависших записей отсутствует. Предварительная проверка worker закрывает обычный случай «worker уже выключен», но не падение между проверкой и отправкой.

Сценарии для staging: отключить broker после проверки доступности, до `.delay()` — запись может остаться QUEUED без сообщения; аварийно завершить worker после установки PROCESSING — обработка может остаться зависшей и блокировать следующий запуск этого курса. Это **вывод по коду**, аварийный fault-injection в production не проводился.

Нужно: надёжная отправка через transactional outbox/reconciliation, lease/heartbeat и восстановление зависших задач, идемпотентная обработка повторной доставки. При проверке не допускать повторных платных вызовов без учёта бюджета. Критерий: после обоих отказов задача либо продолжается, либо переходит в понятный FAILED с безопасным повтором.

**A-02. Реальная AI-генерация и OCR ещё не приняты. ТЗ 34–42, 79, 125.**

Сейчас `AI_ENABLED=false`; наличие кода, mock-ответа и зелёного импорта не подтверждает совместимость текущего ключа/модели, полноту ответа в лимит токенов и качество RU/KZ. Tesseract отсутствует в локальном Windows-окружении; Docker CI проверяет наличие языков, но не качество сканов.

Нужно: после явного включения в ограниченном бюджете сгенерировать небольшой курс из материала без персональных данных, проверить цитаты, недели, ответы, язык, цену и публикацию; отдельно прогнать текстовый PDF, скан RU/KZ и изображения. Подготовленный экономичный режим не менялся и деньги во время аудита не расходовались.

**A-03. Gmail не настроен до фактической доставки. ТЗ 6–7, 54.**

Восстановление работает на сервере: «Забыли пароль» создаёт письмо со ссылкой на 1 час, подтверждение устанавливает новый пароль и создаёт второе уведомление. Но SMTP app password отсутствует; `config.settings.local` использует file backend. Поэтому реальное письмо сейчас нельзя обещать. Наличие адреса отправителя само по себе не подключает Gmail.

Нужно сохранить пароль приложения локально в игнорируемом `.env.local`, перезапустить API/worker/beat и проверить доставку/ссылку/повторное использование. Для студентов вне этого компьютера нужен публичный HTTPS `FRONTEND_URL`: адрес 127.0.0.1 в письме укажет на их собственный компьютер. Проверить также доставку уведомления об оценке преподавателю/студенту согласно событию. Пароль и API key не помещать в Git/отчёт.

**A-04. Production readiness неполный. ТЗ 100–110, 122.**

`backend/config/urls.py:ready` в Redis-режиме проверяет БД и Redis, но не worker, beat и S3. `MailOutbox` прекращает автоматические попытки после пяти ошибок, без отдельной панели/алерта оператору. Docker build/smoke не подтверждает TLS, Gmail, доступность S3, Sentry и восстановление backup на будущем сервере.

Нужно: наблюдение за worker/beat/outbox/S3, понятный статус отказавшего сервиса, алерт для исчерпанных отправок; staging deploy с HTTPS и репетиция backup/restore. Не считать green `/ready/` доказательством работы всех функций.

## Как устроено и как пользоваться сейчас

**Backend действительно Django + Django REST Framework.** React/Vite отправляет запросы `/api/v1/`; Vite локально проксирует их на Django. Авторизация — серверная сессия и CSRF. Django проверяет роль/доступ, работает с БД; Celery выполняет обработку источников, AI и почту. Для production предусмотрены PostgreSQL, Redis и приватный S3; на Windows локально используются SQLite и файловая очередь Celery.

**Ручной курс:** преподаватель открывает «Мои курсы» → «Создать» → курс → «Добавить неделю» → «Добавить тему» → материалы/задания/тесты. В тесте добавить вопросы и варианты, отметить правильные; настроить веса оценивания суммарно 100%; затем «Опубликовать» и назначить студентам/группе. При ошибке публикации нужно исправить указанные данные. AI для этого не требуется. Подробности в [руководстве](USER_GUIDE_RU.md).

**Контент** — информационные блоки публичной главной страницы, которыми управляет admin. Учебные материалы добавляются внутри курса.

**Аудит** — журнал важных действий и изменений, доступный admin. Это не раздел учебного содержимого и не полный журнал каждого запроса.
