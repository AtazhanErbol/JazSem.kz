# Image/dependency review — 2026-10-01

This is a scoped engineering review, **not production release approval and not a clean backend image claim**. Fresh raw Trivy JSON is retained in safe artifacts; condensed findings/digests are in measurements/image-scans.json after final verification. No `.trivyignore` or blanket `--ignore-unfixed` is used. Python runtime/development and npm scans are separate from OS/container scans.

## Changes backed by scans

Pinned Python and unprivileged Nginx base digests. Updated Debian OpenSSL/PCRE packages and Alpine security packages; removed unused Nginx dynamic modules and installed patched Nginx 1.28.3-r7 while preserving its unprivileged configuration. Installers/test tools are absent from the backend production stage; development tooling is separately locked. Runtime is non-root/read-only, `/tmp` only, capabilities dropped, no-new-privileges. Actual startup/OCR/TLS tests must remain green after rebuild.

## Remaining backend native findings

Exact package/version/CVE entries and rationale are in [native-image-review.json](measurements/native-image-review.json). At the review snapshot these HIGH/CRITICAL findings had no fixed version in Debian 13's configured repositories. Do not install unstable Debian packages or silently replace OCR libraries to silence a scanner. This is a bounded reachability assessment from application paths and linked libraries; it is not a proof that every possible exploit is impossible.

- **CVE-2026-6653 (system libxml2):** the OS library is indirectly linked by Tesseract/libarchive. OOXML uses lxml 6.1.3's bundled libxml2 2.14.6, not that OS copy. python-docx and python-pptx instantiate XMLParser with `resolve_entities=False`; no DTD validation/XInclude/XPointer features are invoked. The [Debian tracker](https://security-tracker.debian.org/tracker/CVE-2026-6653) distinguishes the older system branch and the upstream fix. Tesseract receives locally decoded/re-encoded raster images, not arbitrary XML/archive inputs.
- **CVE-2026-74860, 86138, 86139, 86140, 86142, 86143, 86144 (libxml2):** no system Python-libxml2 bindings, XInclude/XPointer processing, schema/DTD validation, custom write callbacks or user URI escaping path. OOXML ZIP expansion is capped at 50 MiB/2,000 entries; parser huge-tree mode is not enabled. The [86138 upstream issue](https://security-tracker.debian.org/tracker/CVE-2026-86138) also warrants monitoring bundled lxml XML code, even though OS scanning cannot inventory that static library accurately. Do not treat absence of a pip advisory as a native-library safety proof.
- **CVE-2026-73066, 88047, 88048, 88051, 88052, 88053 (Tesseract):** affected crafted traineddata paths. Models/languages are installed in immutable image, no user model upload/path override. Review [upstream advisory details](https://security-tracker.debian.org/tracker/CVE-2026-88047) again when model packages change.
- **CVE-2026-36849, 52490 (libtiff):** TIFF uploads are rejected by decoded-format validation. OCR sees verified PNG/JPEG or PDFium-generated raster. tiffcrop CLI is not invoked. [36849](https://security-tracker.debian.org/tracker/CVE-2026-36849) and [52490](https://security-tracker.debian.org/tracker/CVE-2026-52490) describe different TIFF paths; neither is hidden as an unspecified false positive.
- **CVE-2026-66046, 76956, 76957, 93990 (Expat):** uploaded OOXML uses lxml; application does not install custom Expat encoding callbacks or accept arbitrary XML request bodies. [76957](https://security-tracker.debian.org/tracker/CVE-2026-76957) needs those callback conditions. Python/boto XML from storage is within the configured trusted service boundary. Resource limits remain necessary against malformed input; review again if XML endpoints are added.
- **CVE-2026-12064, 8286, 8458, 8927 (curl):** affected native SFTP/STARTTLS/auth connection-reuse paths are not used. OpenAI/S3/SMTP use their Python clients with certificate verification, not libcurl.
- **CVE-2026-88806, 88807 (X11/Xrender):** no X server/display socket or connection in the headless services.
- **CVE-2025-69720; CVE-2026-16742, 54369, 76642, 78408, 78409, 78410, 9538:** local terminal/privileged mount/nsenter/homed/ACL or Perl archive tools, absent from request/worker code. No privileged processes/capabilities or writable application image are granted.

**Enforced review:** `scan_acceptance_images.py` fails for new/unreviewed or fixable production HIGH/CRITICAL entries, changed versions or expired review (2026-10-15). Only exact current tuples are eligible, and all findings remain visible. Re-review after dependency/configuration changes; never extend expiry without analysis. Owner/security acceptance of residual native risk is required before handling real documents. No exploitable application path was reproduced in these tests; this does not replace target security review or native fuzzing.

## Dependency containers

PostgreSQL/Redis/MinIO in acceptance are synthetic services. Their full scans are retained **without claiming zero findings**. PostgreSQL's image includes Go-based entrypoint tooling advisories; Redis image has fixable OpenSSL packages; archived test MinIO has fixable Go/module and server advisories. The lab has no real accounts/materials, MinIO/Redis/PostgreSQL have no host ports in acceptance, and only a loopback HTTPS test edge is published. Development Compose must likewise stay local and never receive real student data.

These images are not production service recommendations or approved deployment components: `compose.production.yml` provisions none of them. The owner must provide maintained, patched PostgreSQL/Redis/private S3 and verify their exact versions/IAM/TLS before release. The fixed MinIO source is retained solely for reproducible S3-compatible tests; replacing the institution's storage product is outside this application change. If the lab is exposed or used with real data, its present exception is invalid and those findings block that use.

## Secrets and telemetry

Gitleaks scans complete Git history and the tracked/unignored working-source snapshot with 100% redaction. Ignored `.env`, private media, test raw traces, mail reset links and dumps never enter exported artifacts. Only counts/timings/status/IDs and allowlisted structured server metadata are exported. Sentry scrubs request bodies, cookies, auth, query strings, student/document data and exception values; tests verify the scrubber. Raw failed browser traces remain ignored locally because DOM/network snapshots can contain credentials; CI exports a sanitized failed-action timeline instead. No real external SMTP or paid provider calls are performed.
