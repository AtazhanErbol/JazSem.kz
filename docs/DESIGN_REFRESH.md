# План обновления интерфейса

Сохранить узнаваемость JazSem и существующее обучение, сделать лендинг содержательнее, а общие элементы кабинета — спокойнее и удобнее. Исходная версия сохранена в GitHub main на `6d13d82`; дизайн выполняется отдельно в `feat/landing-design-refresh`.

## Область изменений

- Включено: лендинг, мобильная навигация, дополнительные редактируемые блоки, типографика, общие поверхности/отступы форм и кабинета.
- За пределами: изменения учебных данных, пересоздание базы, публикация CMS-текстов за пользователя, изменение правил оценивания/доступа, реальные AI-запросы и отправка писем.

## Визуальное направление

Geologica для русского интерфейса, Noto Sans для казахского. Палитра: красный `#e32636`, графит `#24262b`, белый `#ffffff`, бумажный фон `#faf7f2`, вторичный текст `#667080`, разделители `#dfe4e9`. По уточнению пользователя ориентир — [Cecilia Materials](https://www.ceciliamaterials.com/): тёмный просторный первый экран с 3D-книгой, плавающая навигация, крупная типографика и плавные появления при прокрутке. Содержание адаптируется к обучению; кабинет остаётся светлым. Логотип и реакция книги на курсор сохраняются.

Анимации используют CSS transform/opacity и IntersectionObserver. Лёгкий параллакс первого экрана обновляется через requestAnimationFrame, без WebGL, видео и новых библиотек. Настройка reduced motion отключает движение. На телефоне параллакс отключён.

Последовательность лендинга: первый экран → о платформе → возможности → пример учебной недели → подготовка курса вручную/с AI → путь студента → преподавателям и студентам → FAQ → вход. Существующие опубликованные тексты, изображения и дополнительные блоки продолжают приходить из CMS. Новые секции редактируются и скрываются отдельно.

## Действия

1. Проверить Docker, ветки и исходники; сохранить текущую версию с инструкцией установки в main.
2. Добавить два логичных блока и редактирование их текстов/видимости без миграции учебных данных.
3. Обновить стили лендинга, навигацию телефона и общие элементы кабинета.
4. Проверить CMS-черновик/публикацию, локализацию, формы, курсы и существующие frontend-тесты.
5. Проверить Playwright на компьютере и телефоне: меню, FAQ, переходы, ширины и консоль.
6. Собрать frontend, обновить локальный Docker и сохранить результат в отдельной ветке.

Риски: длинные казахские заголовки, узкая шапка телефона, существующие CSS-переопределения и редактирование новых CMS-полей. Проверяются отдельно; тесты выполняются на изолированных данных.

## Проверка результата

- 27 frontend-тестов и 11 backend-тестов редактора лендинга пройдены; ESLint, Ruff и production-сборка выполнены успешно.
- Полный Playwright-прогон: 21 сценарий пройден, без пропусков и повторных попыток. Проверены ручное создание курса/заданий/тестов, публикация/назначение, выполнение и оценивание работ, история версий, приглашения/восстановление пароля через тестовую SMTP-почту, обработка источников и AI с синтетическим провайдером. Устаревшие шаги проверок заменены на текущие подписи и форму оценивания.
- Визуально просмотрены 17 страниц кабинета при ширине 1280 и 390 px. Лендинг проверен на 320, 360, 390, 768, 1010, 1280 и 1440 px на русском и казахском. Проверены меню с Escape и фокусом, FAQ, переходы, книга и reduced motion.
- Настройки полей CMS вынесены в отдельный модуль редактора: примерно 5,5 КБ JS не загружаются посетителям главной страницы.
- Измерения production-сборки: семь холодных загрузок каждой страницы, CPU ×4, сеть 5 Мбит/с с задержкой 40 мс. Новые двуязычные блоки учтены в лимитах исходного кода маршрутов: 535 КБ для лендинга и 660 КБ для входа. Лимиты gzip (170/210 КБ) и всей JS-сборки (800 КБ) сохранены. Это лабораторная проверка, а не измерение скорости на пользовательских устройствах.
- История и исходники проверены Gitleaks: утечек не найдено. `.env`, база, загруженные файлы, снимки экрана и приватные журналы не публикуются в Git.

Данные рабочего Docker не пересоздавались, seed_dev не выполнялся. Публикации CMS за пользователя и реальные запросы AI/отправка писем не производились. После получения ветки достаточно обновить frontend и перезапустить backend; миграций для этих изменений нет.
